# Single-Repo Monorepo

All deliverables — apps, packages, tooling — live together in one git repository.
Changes across package boundaries land in a single commit and are reviewed together.

## Project Structure Expectations

Root is a git repo. Top-level layout:
- `apps/` — deployable applications
- `packages/` — shared libraries consumed by apps or external users
- `tooling/` or `config/` — shared build config, lint rules, TypeScript base configs

Root contains only: workspace config (`pnpm-workspace.yaml`, `package.json` or
`Cargo.toml` workspace manifest), `README.md`, `LICENSE`, `.gitignore`, CI workflows.
No app source at root.

Each package/app in `packages/` and `apps/` follows standard single-package layout
(`src/`, `dist/`, `tests/`). Internal cross-references use workspace protocol
(`workspace:*` for pnpm, path deps for Cargo).

## Decision Norms

Changes that affect multiple packages in one PR are the norm, not the exception.
Monorepo-spanning refactors are preferred over multi-PR cross-repo dances.

Breaking changes to a shared package require updating all consumers in the same PR.
Leave nothing in a broken intermediate state.

## Code Review Conventions

PRs that touch packages consumed by others flag those owners in the review.
The reviewer set scales with the blast radius: a change only affecting one app
needs one approver; a change to a shared utility needs approvers from all consumer teams.

Changeset tooling (or equivalent) captures what changed and at what semver level
before merge.

## Release Cadence

Packages release independently via changeset tooling or similar. A single PR can
bump multiple packages at different semver levels. The CI release job runs after
merge to main and publishes only what changed.

Apps deploy on their own cadence, independent of package releases.

## Documentation Expectations

Root `README.md` lists all packages and apps with one-line descriptions.
Each package/app has its own `README.md` and `CHANGELOG.md` (generated by
changeset tooling). Shared architectural docs live in `.github/docs/` or
`docs/` at root.

## Dependency Philosophy

Internal packages use workspace protocol, never published versions, to ensure
changes are always tested end-to-end before release.

External dependencies shared across all packages are hoisted to root. Package-specific
deps stay in that package's manifest. No phantom dependencies — every import must
be declared.
