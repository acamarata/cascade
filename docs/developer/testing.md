# Testing with internal/testkit

Status: active from Wave 1 (P1-E01-W1-S01-T4). `internal/testkit` is the
shared test toolkit every later package tests against: golden-fixture
helpers and clock injection, plus the lint rules and CI coverage lane that
make the discipline behind them mechanical rather than aspirational
(12-QUALITY-CONSTITUTION.md Art.7.1/Art.7.3).

`internal/testkit` is test infrastructure only. Nothing under it may be
imported from non-test, shipped code (Art.1.1/Art.1.4): its Clock and
golden helpers exist purely so package tests can be deterministic.

## Writing a golden test

```go
import "github.com/acamarata/cascade/internal/testkit"

func TestRenderSomething(t *testing.T) {
    got := renderSomething(fixedInput)
    testkit.Golden(t, "something", got)
}
```

`Golden(t, name, got)` compares `got` against
`testdata/goldens/<name>.golden` in the CALLING package (Go test always
runs with the package directory as its working directory, the same layout
already used by `internal/runtime/testdata/goldens/*.golden`). On a
mismatch it fails via `t.Errorf` and prints both sides. On a missing golden
file it fails via `t.Fatalf` rather than treating "no file" as an empty,
passing comparison.

`testkit.MustRenderLine(name, value)` is a tiny deterministic-rendering
helper used by testkit's own sample golden test
(`internal/testkit/golden_test.go`); most packages will have their own
rendering logic instead.

### Update mode

There is no `-update` flag. Golden update mode is switched by an
environment variable instead: a package-global `flag.Bool` registered
from a non-test file would collide across any test binary that happens to
import testkit alongside another `-update` flag, and would still need the
same CI guard below:

```sh
CASCADE_TESTKIT_UPDATE_GOLDEN=1 go test ./internal/yourpkg/... -run TestRenderSomething
```

With the env var set, `Golden` writes `got` to the golden path instead of
comparing, creating `testdata/goldens/` if needed, and logs what it wrote.
Review the diff before committing an updated golden: the point of the
guard below is that this step can never be skipped by accident.

**It is impossible to accidentally "fix" a failing golden test by having CI
regenerate the golden.** If `CASCADE_TESTKIT_UPDATE_GOLDEN=1` is set AND the
standard `CI` environment variable (set by every GitHub Actions job) is also
set, `Golden` refuses outright via `t.Fatalf` instead of writing anything.
Goldens are updated locally, reviewed as a diff, and committed like any
other source change, never generated by a CI run.

## Clock injection

`internal/runtime` owns the Clock interface production code depends on
(`internal/runtime/clock.go`, `SystemClock`/`FixedClock`). `internal/testkit`
provides a structurally identical `Clock` (`Now() time.Time`) plus
`RealClock` and `FrozenClock`, so any OTHER package can accept clock
injection without importing `internal/runtime` for a type that has nothing
runtime-specific about it: Go interfaces are structural, so a
`*testkit.FrozenClock` already satisfies `runtime.Clock` too.

```go
import "github.com/acamarata/cascade/internal/testkit"

func TestSomethingTimeBased(t *testing.T) {
    clock := testkit.NewFrozenClock(time.Date(2026, 9, 2, 12, 0, 0, 0, time.UTC))
    svc := NewService(clock) // svc's constructor takes a Clock-shaped interface

    clock.Advance(90 * time.Minute) // deterministic, no sleeps (Art.7.3)
    ...
}
```

Domain logic may never call `time.Now()`/`time.Since()` directly; see
"No bare time.Now" below.

## No bare `time.Now`, no unseeded `math/rand`

`.golangci.yml`'s `forbidigo` settings forbid two call shapes in non-test
domain logic:

- `time.Now` / `time.Since`: inject a `Clock` (either
  `internal/runtime.Clock` or `testkit.Clock`) and call its `Now()` instead.
- The global `math/rand` source (`rand.Int`, `rand.Intn`, `rand.Float64`,
  `rand.Seed`, …): inject an explicitly seeded `*rand.Rand` instead
  (`rand.New(rand.NewSource(seed))`); its method calls (`r.Intn(...)`) have
  a variable receiver, not the `rand` package identifier, so they never
  match the rule.

Both rules are exempted inside `_test.go` files and at the two paths that
ARE the Clock abstraction (`internal/runtime/clock.go`,
`internal/testkit/clock.go`); see `.golangci.yml`'s `exclusions.rules`
entries for the exact, anchored regexes (never an unanchored substring
match; see the comment on the pre-existing `testdata` exclusion for why
that matters). `internal/testkit/lintwall_test.go` proves both rules fire on a
seeded-violation fixture and do not false-positive on any of those
legitimate uses, by running the repo's own committed `.golangci.yml`
through the real `golangci-lint` binary against a disposable temp module,
never a re-typed approximation of the config.

## Coverage lane

The `coverage` job in `.github/workflows/ci.yml` runs
`go test -covermode=atomic -coverprofile=coverage.out ./...` on every push
and uploads the profile as a build artifact. This lane MEASURES coverage;
it does not itself enforce 12-QUALITY-CONSTITUTION.md Art.4's per-package
floors or ratchet; that is a later ticket's floor-gate, which consumes
this lane's profile. Run the same command locally before pushing:

```sh
go test -covermode=atomic -coverprofile=coverage.out ./...
go tool cover -func=coverage.out | tail -1   # total coverage
go tool cover -html=coverage.out             # per-line, in a browser
```
